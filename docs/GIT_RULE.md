# GIT RULE

## ブランチ戦略

- GitFlow に準ずる
- default ブランチは`develop`

## コミット戦略

- revert などを考慮してコミットは機能の最小単位で行う
- コミットの順番は依存関係を考慮する
- コミットメッセージはどんな実装を行なったのか一目でわかるようなものにする（悪い例：xx を更新、良い例：xx のため xx を変更）
- コミットメッセージの日本語で prefix は不要
- `add` と `commit` はワンライナーで行うこと

## その他

- アクセスキーなどの機密情報は Git の差分に含めないこと（.gitignore を用いる）
